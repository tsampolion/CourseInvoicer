# Code audit: `Rebuild_v2` at `e80ab2b9` (2026-10-18)

Read-only audit of the whole code base. Five areas (architecture, business rules and data, security
and privacy, UI/UX and accessibility, performance/tests/build/docs) were reviewed in parallel. The
high findings were then checked against the code by hand. This file is a plan. It changes no code.

## 1. Summary

- No critical issues. The architecture rules hold: `:core` has no Android imports, nothing uses
  `GlobalScope` or `runBlocking`, and no ViewModel writes to a repository directly. The manifest,
  FileProvider and cloud-backup exclusions are clean, and no SQL is built by interpolation.
- The biggest risk to data: some lesson writes check a rule (R7, R8) and then write the row without
  re-checking it inside the transaction. In a single-user app the window is small, but a guard in
  SQL costs one clause.
- Restore validation (R11) is weaker than typed input in two places: a paid lesson with a zero fee,
  and an unbounded fee.
- `stateInCatching` stops a list from refreshing after one upstream error. Exported PDFs are never
  deleted from the cache.
- The UI is English only and the strings are hard-coded. That is already on the backlog (spec §5)
  and is the largest piece of work here.

- **PDF retention (S1):** delete exported PDFs after a day, or at every app start?
- **CI secrets (S5):** use a protected GitHub environment for the signing key? That is a
  repository-settings change only the owner can make.
